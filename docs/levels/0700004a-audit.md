## §1 The doors (162) — the mechanism, newly decoded for this level

`Door_Create` 0x136100 maps the level_tag params: p0 → obj+0xF6 (0 = swing via `Door_SetupSwing`,
else slide), p1 → data+0x6A, p2 → data+0x66, p3 → data+0x68, p4 → obj+0xFD bit 8 (portal),
p5/p6/p7 → data+0x60/0x62/0x64 (sound ids, 0 → 0xFFFF = none), p8/p9 → data+0x70 bits and
`(p8|p9)>>2 & 1` → obj+0xF4 = 2 (bit clear) or 4 [M decomp 0x136100].

`Door_Update` 0x1363c8 per tick:
- p2 (data+0x66) non-zero arms the approach/proximity block (channel on → `Door_Activate`; off and
  class bit 2 → the closeness scan over classes 0x12/0x03/0x02 opens/closes). Every 4a door has
  p2 = 0 → the block is skipped entirely.
- p3 (data+0x68) non-zero arms the one-shot unlock: on the channel's on-edge (prev off) it calls
  `Door_Activate`, clears data+0x68 and sets data+0x70 bit 0x10 (frozen); the "unlocked" text
  0x2000003 is shown **except on GameState 0x7000014 / 0x700004a** [M 0x1363c8:101–107].
- the tail ORs obj+0xF4 into `DoorGroupsStates[p1]` every tick [M 0x1363c8 tail].

`Door_DoMsg` 0x135f18 (the E handler): refuses while p3 is set and its channel is off (locked);
otherwise reads the group state word `DoorGroupsStates[p1]` (p1 non-zero) and shows the refusal
text 0x200000b unless it equals 4. Every 4a door has class word 2 → E always refuses with the
text (and the locked check never even engages for p3 = 0 doors) — these are remote-only doors.

`Doors_Calc` 0x135fe0 (per frame, after the updates): for each door with p1 ≠ 0, every other door
with the SAME p1 that lacks bit 0x10 is slaved to it (matrices +0x50/+0x58, counter +0x72, class
word, `Door_Interp`); then bit 0x10 is cleared on all doors. So opening one member of a pair
drags its twin — the group word is the OR of the members' class words.
