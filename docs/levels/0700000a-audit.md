# 0700000a behaviour audit (level-0a-audit)

The level's own census lives in `docs/levels/0700000a.md` (§Census). This audit is the per-placement
check that task level-0a-audit asks for: every main-map placement (800 [D]), every script stream and
every mission record, with the game's creator in `parsemap_create_dynamic_objects` 0x1d04f0 / the
static path, its update and use/damage handlers [M], and the port's handling — GAP column included.

Method: three legs, all cited. (1) The game side: the 0x1d04f0 dispatch read from
`work/decomp/ACTION.ELF/001d04f0_*.c`, each create function's registration traced to its class byte
and the `control_funcs` row unpacked from the raw ELF (`work/elf/ACTION.ELF`, table @ 0x26f890,
rows ×12 bytes: update/collide/delete) [M]. (2) The disc side: `nf-extract placements-all /
triggers / nis / script-info / level-summary` over `0700000a.bin` [D]. (3) The port side: per-class
reads in `crates/nf-game/src` + `crates/nf-view/src/scene.rs`, file:line cited. The per-tick call
order follows `Drones::tick_inner` (drone.rs:15168).

## 1. The dispatch and the calltree sweep

## 2. Corrections this audit produced

1. **0xdb is `Door_Create` 0x136100, not a mux.** The 19 0xdb placements are all doors [D names:
   office_a_door1/2 … Door_Guardroom]; the level doc's census never mislabels them, but the
   "mux/inverter" guess this task inherited is dead: the muxes are 0xec/0xed/0xef
   (`Trigger_MultiplexIn` 0x1b2c68 AND / `Trigger_MultiplexSIn` 0x1b2e08 SEQ / `Trigger_MultiplexOrIn`
   0x1b2d38 OR) and the inverter (0x41) is absent from 0a [D census].
2. **The level doc's "no fuseboxes (0x31) / no grapple points (0x3A) on the main map" line is wrong
   [D].** The 800-placement census carries **13× 0x31 and 1× 0x3a** (GRAPPLEPOINT_SkyBridge #785).
   Both are handled by the port (see §3 rows). The 13 0x31 placements carry no params, so
   `FuseBox_Create` 0x1b0448 creates a class-0x3c object whose `SP_Create` gets hash 0 —
   `SP_Create` 0x1dc7e0:69-71 substitutes dummy hash 0x2d6200 which never loads, so the game's
   objects are inert invisible shells (obj+0xD8 = 0, no script, no wires, nothing to E). The port's
   skip of param-0-less 0x31 (fusebox.rs:97-106) is behaviourally equivalent; the objects' names
   (camera(a)_OFF, SCRIPT_KeyboardMH_OFF, M.Hatch Indicator locked/unlocked …) are script-marker
   art whose swap-in halves ride the SP scripts' entity shows [D §4].
3. **The level doc's "0x27 GT not ported" row is stale.** `gt.rs` exists: 0x27 placements create
   the turrets (drone.rs:12578-12636), `GT_Update`'s port tracks Bond/guards with LOS and fires
   real bullets (drone.rs:15273-15392), and `cameras_turrets_census_live` pins the level's census
   row (2 cameras, 6 turrets). The turret MESH draw is the remaining census row `0a(12)`
   (placement-draw-census.md:125) — draw-only, listed in §5.
4. **Trigger params are reshuffled at create** [M 0x1b2b88/0x1b2aa8/0x1b2c68/0x1b2e08/0x1b2d38/0x1b2950
   — each first `amemcpy(rec+0x2C → TmpParam @ 0x319b88, 0x84)`, then overwrites p0 with the
   subtype (1 TouchOnce / 2 Touch / 3 AND / 4 SEQ / 0xA LOADLEVEL / 0xC OR) and shifts the channel
   words up one]. So a placement's p0 is the OUT channel, and #59's next-level code 0x0700000B
   rides p0 (invisible in the trigger dump's out column) [D].
5. **The level doc's MusicTrigger row ("presentation, music unported") is stale**: the port creates
   the trigger with the game's own create gate (worldobj.rs:414-420, `p2 == 0xff || p0 == 0 → no
   object` [M 0x1b30e0:12-16]) and ticks it into the music event board (worldobj.rs:466-474,
   WorldObjects::tick ← drone.rs:15633). Playback plumbing is view-side music.rs.

## 5. The gaps

**GAP-1 (large, code): the keypad E-path — `Lock_Activate` 0x1aed00 has no port function.** The
chain [M]: E at a lock with class-3 (player) user and no menu open (0x1aed00's gates) → state
(+0xF4) 0 or 5 and the gate channel (`ext+0x02`) off → **state := 3** and the user saved to
GlobalVars / DAT_002a37d4; state 3 (`Lock_Update` 0x1ae3d8:236-258) copies the lock's keycode
(`KeyCodes[p0·5]`, 5 bytes) to 0x2a37d8, expects 4 digits, **creates the keypad menu**
(MenuManager_Create, action 0x40000021) and posts the keycode hint (Txt_BindLabel 0x2000014 — the
same label the Q-Worm install uses) when `KeyCodes[p0·5+4] != 0`; state 4 (:261-296) matches the
entered digits and on success calls `Lock_Unlock` 0x1b0650 (writes the unlock channel), deletes
the menu, plays the unlock sound. On 0a this is doors #724 (ch 48) and #725 (ch 49) [D — the locks
p5 pair]. The port has the lock object, the laser burn, the re-lock and the decryptor scan
(lock.rs) but no E activate and no keypad UI: on a real pass the two keypad doors can only be
opened with the decryptor gadget, while the game offers the code entry. Why not fixed here: the
digit-entry UI is a MenuManager flow (presentation + input), and the sim-side state machine
without the UI has nothing the player can drive. Follow-up task: the keypad menu + the state-3/4
machine. Live checks: §6.

**GAP-2 (medium, code): the gold-medal create gate for kind-6 pickups.** [M 0x18dda0:92-96:
`if (kind == 6 && !PlrStats_HasGoldMedal()) return 0`; PlrStats_HasGoldMedal 0x199a40 =
Menu_HasMedal(Mission_BaseMapHCode(), 3, 0)] — without the current mission's gold medal the three
"Pickup 007" placements (#726-728, p0 = 6 [D]) never exist. The port's `create_placed`
(pickup.rs:166) creates them unconditionally and the D-004 decision lets the take through
(pickup.rs:557/600 — the take-path note). Not fixed here because the gate has cross-level blast
radius: three live tests assert a BOND_BONUS exists/takes (interactables_07000011:283-291,
fix_progress:88, mp_pickups_visible:102), and an MP arena's kind-6 would read a mission-base-map
medal that MP does not define — the medal store and its MP rule need their own task.

**GAP-3 (draw-only): the hologram rotor's spin is not posed onto the drawn mesh.** The sim angle
ticks (worldobj.rs:452, rotor_update 0x18f568's law) but the drawn instance holds the static
placement matrix (scene.rs MISC pass 8043/8122). Mesh: placement #93 `office_N_hologram`,
object index 35, hash ffffffff (by-index resolution [D placements]). The main agent's render
should show the hologram at a rotated yaw after a few seconds of play (§6).
