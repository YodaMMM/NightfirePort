# 07000041 — the per-placement behaviour audit (level-41-audit)

Every main-map (m99, archive map `01000058`) placement of 07000041 [D], one row each, against the
game's own code [M] and the port's — same method and conventions as docs/levels/07000014-audit.md.
The [D] rows come from the new census probe `census_07000041.rs --ignored` (NF_ISO onfoot image):
**120 placements, 35 kinds**; positions and params verbatim. Per-kind game chains re-verified this
session against work/decomp/ACTION.ELF (the creator dispatch `parsemap_create_dynamic_objects`
0x1d04f0's cases, the static path 0x1d1998, and each create/update/use function cited inline).

**The param-struct mechanism** (the key to every "+0x2c" claim — it retracts the level doc §6's
spawner paragraph): [M 0x1d1b68 parsemap_block_map_data_dynamic:61-76] memsets a 0xb0-byte struct
per placement and writes **param value k at struct+0x2c+4k** — that struct is what every creator
receives as its "level_tag". A creator's `*(rec+0x2c)` read is **param slot 0** (zero when the
placement has no params); the raw record words are never read by the dynamic path.

Census notes vs docs/levels/07000041.md: the doc's census list was partial and §6 carried two
stale claims (the 0x71 "spawners" and the "#82-#85 third icons") — corrected in the kind blocks
and the report; the doc §6 script id list is also wrong (the real kind-7 set is
0600004f/6f/27/44/45/52/7c4 — see the Scripts section). **NO 0xdb, NO 0xf1, NO 0x0f, NO 0xe8 —
and no 0x29/0x2e/0xdc/0xdd/0xe5/0xe6/0xe9/0xf5-0xf8 rows on the main map** [D]: the
characters/doors/switches/locks families the task lists do not exist on this wrapper.

## The param-struct mechanism (the key to every "+0x2c" claim)

[M 0x1d1b68 parsemap_block_map_data_dynamic:61-76]: per placement the loader memsets a 0xb0-byte
stack struct, copies the path fields, then writes **param value k at struct+0x2c+4k** (index from
the param's index halfword). That struct — NOT the raw placement record — is what
0x1d04f0 hands every creator as its "level_tag". So a creator's `*(rec+0x2c)` read is **param
slot 0** (zero when the placement has no params). The raw record words at +0x24..+0x44 are never
read by the dynamic path (placement.rs's `extra` is port-side bookkeeping). The static parser
builds the same struct [M 0x1d1998:71-80].

## Port GAPs

1. **No stream GAP**: every op the 7 scripts use (Wait/Marker/End, Entity/EntityEnd, Event 0x03/0x0f,
   Light + 0x1a-skip, Sound/SoundEnd) is decoded by `crates/nf-formats/src/nis.rs` and handled by
   `crates/nf-game/src/nis.rs`. The Event writers the level *doesn't* use are implemented too
   (0x11 → `ch.set_script` :959-962, 0x0d :956, 0x12 → LoadLevel :966) — a channel write would NOT be
   dropped if one existed.
2. **Nothing runs the 7 scripts — on the disc or in the port.** Zero class-0xd9 placements with a real
   script hash in all 66 maps; the two 0xd9 SPs carry the 0x06000000 sentinel; no switches (0x29) or
   fuseboxes (0x2c) reference scripts. The port mounts exactly those 2 dead players and leaves the lib
   idle — faithful to the disc. The doc's §2 sentence "ch 0x01 drives the level's 7 scripts" should be
   weakened: nothing mounts a listener on ch 0x01; the consumers of ch 0x01 are the interactables the
   tests already cover (turret #111 arm, DynoRod #117 gate, icon #105 on-ch, voices #115/#116).
