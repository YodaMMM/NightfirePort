# 07000007 behaviour audit (level-07-audit)

Every placement on the level's main map (`01000097` block 0x1A, 513 records [D fresh parse — kind
histogram identical to the §7 census in `07000007.md`]) against the game: the creator in
`parsemap_create_dynamic_objects` 0x1d04f0 or the static path, the update, the use/damage/event
handlers, and what the port does. Then the level's scripts (every stream's ops) and the mission
record. Evidence: [M] decompile `work/decomp/ACTION.ELF/<addr>_<name>.c` (file:lines), [D] disc
bytes (ISO `FILES.BIN` → level/pack archives, placements), [L] live EE snapshot, [S] suggested —
never a pass/fail assertion. The port's behaviour is cited file:line (crates/nf-game, crates/nf-view).

## 0. The dispatch [M 0x1d04f0]

Each placement record is 0x4c bytes + param pairs ([M 0x1d1b68:64-96] — `parsemap_block_map_data_dynamic`):
type word @+0x08 (the dispatcher switches on its **low byte**), position @+0x0c/+0x10/+0x14, second
vector @+0x18, quaternion @+0x24, fourth vector @+0x34, path n/idx/ptr @+0x40, param pairs from +0x4c
scatter to `PLACEMENT+0x2c+4k` (so **pN = u32 @ +0x2c+4N** [M 0x1d1b68:64,74]). Records with the
0x8000 type bit go to the STATIC path instead ([M 0x1d1b68:93-96 skips `& 0xa000`; 0x1d1998:92]):
`parsemap_block_map_data_static` 0x1d1998:93-120 builds a draw-list cel (`build_alloc_cel` → the
`glb_world` list, bbox + render flags + position/orient) — **draw only; collision is the separate
`parsemap_block_Coll_Data_New` 0x1d1810**. Two passes over the dynamic list: the create flag is 0 in
the map-parse (dry) pass and 1 on load ([M 0x1d04f0:544-545]; only case 0x20 pre-registers breakable
data in the dry pass [M 0x1d04f0:71-73]; 0xde creates in both). No default arm — unlisted type bytes
are dropped silently, which is how 0x47 reaches the static path ([M 0x1d00c0:122-143
`parseentity_fixup_entity`, type 0xc047 → cel flags 0x804c047, 9 param bytes into the cel render
struct +0x98, +0x90 = −500.0]).

`NDrone2_DoCollision` 0x149ec8:10-37: guests (dtype 10) are solid **when within 2.0 of a player**
(`DroneFunc_NearPlayerCollision` 0x14b190:10-20) and beyond that only when their current anim lacks
the 0x2 flag. During an NIS the freeze clears the solid flag [M `Drone_CollisionHandler`
0x140968:62-64] — Bond passes through frozen actors. The port: **nothing** — the only near-player
gate (`near_player_collision` drone.rs:2285) has no live consumer (drone.rs:5675); Bond walks
through the crowd. → **GAP-1**, the level's biggest behavioural delta.

## 4. The gaps

1. **GAP-1 (large — its own task): guest/Bond cylinder collision.** The game blocks Bond with
   per-drone cylinders (r 0.4; solid within 2.0 of a player for anim-flag-0x2 drones; both sides
   respond) [M the chain in §1]. The port has no player-drone collision at all — the unused
   `near_player_collision` (drone.rs:2285) is the 0x14b190 gate with no consumer. Needs: the
   cylinders as colliders in Bond's move pass + the drone-side response + the NIS-freeze
   non-solid rule (0x140968:62-64). A live check (below) should confirm the 2.0 gate on hardware
   before the fix.
2. **GAP-2 (fixed this task): the cut-scene mission-timer pause.** Event 4's arm is
   Player_Disable + `PlarStat_LogTimerPause(0)` [M 0x1d94c0:118-121] and `Script_Free` unpauses
   [M 0x1da880:44-48]; the accumulator runs only while the pause byte is 0 [M 0x1995a0:9-14]. The
   port's PlayerDisable/Enable never touched `progress` — the clock counted through both of this
   level's scenes. Fixed in scene.rs (`stats[0].log_timer_pause()` / `log_timer_unpause(now)`);
   pinned by `cutscene_timer_pause_live` (the frozen clock across the real SP #420 window, the
   restart at the hand-back).
3. **GAP-3 (medium — its own task): 0x3b draw linkage.** The sim is exact (`DynObject::tick`
   worldobj.rs:160-197); nf-view never reads it (no `dynobjs` consumer): gated #495 (rope barrier,
   gate ch 21) never APPEARS at Drake's reveal; deleted #496 (blocker, mode 0, delete on ch 0x48)
   keeps DRAWING after the delete; #460-#466 keep drawing if ch 1 ever fires. Needs per-tick
   placement-keyed instance visibility in the render path (the build-time skip at scene.rs:8074 is
   one-shot). Visible — verify with renders (spots below).
4. **GAP-4 (small, visual): guest idle faces.** Idle anims carry no face window → neutral frozen
   faces while idle (documented scene.rs:9762-9765); talk faces work (guest_faces_live). Needs a
   face window for the idle set + a render check.
5. **GAP-5 (large — its own task): the tux skin 0x050000d.** `Player_Init` 0x1910f8:96-107 applies
   it at spawn and BOTH cut-scene scripts animate it (0x06000072 stream 3, 0x06000073 stream 3).
   The port has no third-person Bond body at all (first-person view model only), and 0x050000d
   appears nowhere in the crates. Skin pin (the value reaching the player record) is testable; the
   picture needs a render.
6. **GAP-6 (latent, generic, small fix): DoBreak scans only script entities.** The game's
   `Break_DoBreak` 0x12c168 scans the CONTROL list (placed 0x20s AND script entities); the port's
   arm (drone.rs:14647-14673) walks `scripts.objects.list` only. NO 07000007 script fires event
   0x0A [D §2] — latent here, a trap on other levels. The arm's own header note already documents
   the divergence.
7. **GAP-7 (note, deliberate): the SP loadable-pack lazy stream.** The game streams 0x06000072/73
   through the loading screen on first trigger (`GameFlow_PushState(12.0, 0xD, 0xFF)` once,
   [M 0x1dbda8:99-104]); the port loads both packs eagerly (lib.rs:1151-1197). Content-identical;
   only the screen and the timing differ. Not a behaviour gap on any shipped route.
8. **GAP-8 (note): SP_Hit touching-object bits 8/0x10 unmodelled** (nis.rs:1423). No 07000007
   user (masks are 1 and 2 only). Bit 2 IS ported (corrects the old §3 note) and pinned by
   `urn_break_live`.
