The level's own census lives in `docs/levels/0700000b.md`. This audit is the per-placement check:
every main-map placement (380 [D]), every script stream (14 in the bin + 2 in the packs), every
mission record — the game's creator in `parsemap_create_dynamic_objects` 0x1d04f0 / the static
path, its update and use/damage handlers [M], the port's handling, GAP column included.

Method, the sister audit's three legs (0700000a-audit.md): (1) the 0x1d04f0 dispatch read from
`work/decomp/ACTION.ELF/001d04f0_*.c`, class bytes + `control_funcs` @ 0x26f890 re-unpacked from

`0700000b.bin` [D — note the NIS dumps print params in LOWER-HEX, so event `[0x77,0]` is ch 0x77,
not 77 decimal — this settles the level doc's ch-0x4D reading, §2.4]; (3) the port per class,
file:line. Tick order per `Drones::tick_inner` (drone.rs:15168).

## 2. Corrections this audit produced

1. **0x21 is NOT breakable-family: it is `Ripples_Create` 0x1acc90** (water-ripple particle
   emitters; p0 = radius, p1 = interval, both defaulted when 0 [M 0x1acc90:20-36]; the update's
   `Rand(ext[1]/FRAME_RATE_MUL) == 0` gate spawns the ripple puff [M 0x1ac028:31-46]). The port
   has them (`world_fx.rs` `RippleFx`, world_fx.rs:539-544/688+) — but with a counter-hash instead
   of the shared RNG (world_fx.rs:37-47, a deliberate determinism-preserving substitution: the
   game's ripples DO consume the shared `Rand` [M 0x1ac028] and would shift every downstream draw;
   the port's substitution is a documented deviation, listed in §5 GAP-3).
2. **0xE6 is cover nodes, not hurt volumes.** The level doc's census row "0xE6 Hurt … ported
   (hurt.rs)" (0b.md:167) is wrong on both halves: 0xE6 = `Drone_CoverLowNode` 0x137340 — an AI
   cover record (no object; p0 picks lean/crouch/stand anims from LOW_ANIMS 0x2f4540, p4/p5 = the
   on/off channels [M 0x137340:64-110]) — and the port builds them as `CoverNode`s (cover.rs:46-77,
   142-145), consumed by guard cover selection. Hurt is kind 0xE4 (hurt.rs:107) and 0b has NO 0xE4
   placements [D census].
3. **The roof cut-scene's arming is the game's own law, not a port stand-in.** `Trigger_Calc`
   0x1b1900 hard-copies **ch 0x34 → ch 0x2D on 0700000b** [M — the level latch, the same function
   the port cites at triggers.rs:706; the disc carries no 0x2d writer in the 60-record trigger dump
   [D]]. The port's comment called it "the stand-in for #177's unwritten gate writer"; it is the
   game's hard-coded latch, now pinned by a unit test (§7).
4. **The vent SP script's channel write is ch 0x77, not ch 0x4D.** The level doc reads 060009f9's
   event 0xD param "77" as ch 0x4D (77 decimal); the NIS dump prints lower-hex [D], so the write
   is **ch 0x77 = 0 — the SP clearing its own out channel** (SP #326 out 0x77 [D placements]) —
   the one-shot re-arm law, not an objective channel. Doc erratum fixed (§7).
5. **The level has no LOAD_LEVEL and no exit placement** [D: no 0xE8 kind, no type-0xA trigger
   record, no event 0x12 in any referenced script]: 0b ends through the mission layer — ch 0x5A
   (the parachute jump) + the objective ANDs → ch 0x64(100) → `LevelToEndTo(0x0700000b) =
   0x0730000b` [M 0x182c60:99-101], the driving hand-off. The level doc's route section says this;
   now proven from all three dumps.
