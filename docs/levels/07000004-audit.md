# 07000004 decomp audit (level-04-audit)

The level's kind-level census lives in `docs/levels/07000004.md` (the interactables census + the
exit route). This audit adds what that doc does not carry: the **per-placement** table (all 70
main-map placements [D]), the **scripts' streams decoded op by op** (the camera streams, the
sound lines, the hand-backs), the mission record, and the GAP list with this session's fix.

Method: `crates/nf-view/examples/dump_07000004_audit` (scratch, uncommitted) reads the disc parse
of FILES.BIN entry `07000004.bin` (nf-formats `Level::parse`, main map `010000c5`, **70
placements, 0 unresolved** [D; the other 49 maps carry 0 placements — the interactables
prototype map's parked objects are DEAD data per the census doc]); the per-kind creators are read
off `parsemap_create_dynamic_objects` 0x1d04f0's dispatch [M] (case → call); the port side was
grepped per row and exercised through the level's own tests (walkreal/interact/walk 07000004 +
this task's dialogue pin). The kind byte is the placement's flags low byte, 0x8000 = creates a
cel [D parse; the dispatcher's `param_3`]. Placement indexes below are the parse's own `index`
field — it repeats across same-kind rows (the doc's older #N numbering differs; do not mix them).

## 4. The gaps

**GAP-1 — a stream's second sound line never started (FIXED this task, `e4127e84`).**
`Script_SoundStart` 0x1d8820 clears the stream's sound handle (+0x10 = 0) at its top, BEFORE the
start gate [M 0x1d8820:19]; the port gated on `sound_id.is_none()` without the clear, so any
script stream carrying TWO lines lost the second: 07000004's story stream 15 starts 0x5e @298 and
0x134 @654 [D 0x06000082 decode] and the 0x134 start was gated off — the cut-scene dialogue
dropped a line mid-scene. Fixed in nis.rs's op 0x16 (the clear + the decomp citation); the pin
`crates/nf-view/tests/audit_07000004_live::the_intro_and_story_scenes_play_their_scripted_lines`
walks the real path and asserts every line's id and tick window (intro 0x50a exactly once at its
authored frame 57; the story's first line ≈500+43; all eight story ids; the 0x172 NIS music and
its `SfxNisMusicTrigger`). The sound/cut-scene neighbourhood re-run green on the fixed tree:
cutscene_skip_audio_live 3/3, fix_cutscenes2_live 4/4, movie_audio_layout_live 5/5,
fix_audio2_live 10/10, walkreal_07000004_live 3/3, interact_07000004_live 2/2,
walk_07000004_live 3/3.

**GAP-2 — the two rigid-body lamps (`RB_Create` 0x1d6bf0) are unported (large; own task).**
Placements #26 ×2 "rb_whitelamp" at (−12.05, 7.86, 23.03) / (8.01, 7.86, 23.03) params (1,0,1,1,
0xffff) [D]. The game builds a full rigid body: `RB_Create` 0x1d6bf0 → `RB_Init`/`RB_Update`
0x1d6e38 → `RB_ApplyImpulses` 0x1d6ff8 → `RB_RestingContact` 0x1d7168 [M] — a whole physics
system (levels.md §7.1). In the port nothing is created and nothing draws: shooting or walking
into the lamps does nothing. Fix shape: the RB machine (state, impulses, resting contact) as its
own module behind the same dispatcher case; until then the lamps need at least a static cel so
the carpark shows them (draw-only stopgap — the mesh hash is not on the placement; RB_Create
resolves it through the celglist [M] — a live check can dump obj+0x80/glist at creation).

**GAP-3 — the trees' sway-anim runtime is not ported (draw-only; own task).** #21 ×2 model
0x0500003, sway anim 0x0600008c with the 0x0600008d `Rand_Random` swap [M `Env_Tree_Create`
0x17c200:29-35]. `world_fx::TreeFx` carries the hashes and the pause arm (every level but
0x7000043 pauses the script with a random phase [M :44-52]) but the world-object anim runtime
(the sway actually moving the mesh) is not ported [S unverified]: the trees are static meshes.
Fix shape: the AnimObjectNew/AnimScriptAdd path for world objects (the same machinery the NIS
anim streams use — nis.rs `anim_start` — retargeted to a world object), or a documented
stand-in sway.

**GAP-4 — the cut-scene camera hand-back is partial (verify visually; the ledger row).** The
verify ledger's `Camera_UpdateAll` 0x1e2d78 row: "Only camera 4 (script) and the Bond-follow
camera; … no camera stack pops on Script_CameraEnd beyond the object delete" [M docs/verify/
ledger.md]. Both 04 scenes end with a camera stream (the intro keys 0..32, the story 0..77) and
hand back to Bond's follow camera; the port's Script_CameraEnd clears the camera-active flag and
deletes the object, which the walk tests survive — but the visual hand-back (no pop/flash, the
follow camera resuming at the story's exit pose) is a RENDER question still to settle.
Render spots: `--bond 1.87,5.84,41.07,-3.142,0` at load (the intro's opening
frame: the camera should be the scripted key pose, not the follow camera), `--bond
-3.87,5.44,30.30,0,0` after the story settles (the assassination framing, Bond beside the target,
the target standing), `--bond -8.0,4.6,33.0,2.37,0` (the carpark: the limo parts + the two
whitelamps — GAP-2's missing art), `--bond 4.6,4.6,27.4,0,0` (the trees at the pond, GAP-3's sway
subjects).
