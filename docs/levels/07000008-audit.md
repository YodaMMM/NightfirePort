## 2. Corrections this audit produced

1. **#234 `SmallExplosionBox` is an INPUT of ch 137, not its writer.** The level doc's §2 chain
   ("the SmallExplosionBox #234 → ch 137 opens the GuardRoomDoor") had the direction reversed:
   `Destroy_Create` 0x12c318 scatters param 0 to tag+0x12 (the death write [M 0x12c318:35,
   `Destroy_Update` 0x12c4f8:23]) and **param 1 to tag+0x10 — the external-kill LISTENER**
   [M 0x12c318:36, `Destroy_Update` 0x12c4f8:30-35: the channel ON → `Destroy_Smash`, the word
   clears]. #234's params are (p0 = 0, p1 = 0x89 = 137, p3 = 10000, p5 = 0) [D the census] — its
   death write targets channel 0 and **the fusebox #219's ch 137 smashes the box**. The level doc
   row still carries the old reading; this file and the code comments carry the correction.
2. **The F5 death does not need the kill floor.** The death NIS's own stream writes the death
   channel — event 0xD params (62, 1) at the script's tick 89, stream 6 [D 0x06000991, decoded on
   the real walk via NF_SCRIPTLOG]. `Mission_Update`'s ch-0x62 arm fails the mission from there
   [M 0x182c60:21-43]. The body hold during the NIS is the game's own law (event 4 disables the
   player [M 0x1d94c0:119; `Player_Update` 0x193600:80-89 returns on the 0 byte]; no event 6 in
   the stream [D], so `Script_Free`'s 0x100-gated enable [M 0x1da880:44-49] never runs). The old
   "the port has no death after a death NIS" notes (`docs/levels/07000008.md` §7's blocked-kill-
   floor finding and the old `hurt_07000008_live` header) were wrong about the fail — the fail
   path was already fully wired and is now pinned end-to-end.
