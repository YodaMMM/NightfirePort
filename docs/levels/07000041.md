## 7. How the game routes around this wrapper

The game's own flow never loads 0x07000041 through the ported paths: no 0x71/0x72/0x73 movie code
resolves to it (`GetLevelToLoadFromMovieCode` 0x1d3560: the 0x73 table → 0x7000048; the default
returns `GameState+8 & 0xff00ffff`), `sp_level` (0x2df2e0) has no 0x41 row [L ee_start], and no
disc byte pattern of the code appears in any script stream. The campaign's route is:
0x07000016 completes → outro movie **0x07300017** (07300017.PSS [D MOVIES/30_FPS]) → phase 2
resolves **0x07000048** (the front end) [M 0x182c60 case 6 → 0x1d3800 → 0x1d6360 phase 2 →
0x1d3560] → the front end starts 0x0700001b whose briefing code is **0x07100018** [M 0x1d3800's
`case 0x700001b: 0x7100018`; 07100018.PSS [D]] and whose phase-0 remap lands on 0x0700001b [M
0x1d6360's `uVar7 == 0x7000018 → 0x700001b`]. GameState+0xc == 0x07000041 in the AI/sound/dev code
([M 0x147c48/0x147f58/0x1dceb8/0x1bcfa8]) proves the level ran with live AI at some build; on the
retail disc its entry/exit are not reachable through the game's own flow.
